### Гайд по работе с Git для команды (Secure Pass & Vault)

#### 1. Первичная настройка (Сделать один раз)
Склонируйте наш репозиторий с GitHub к себе на компьютер:
```bash
git clone <ССЫЛКА_НА_ВАШ_GITHUB_РЕПОЗИТОРИЙ>
cd <название_папки>
```

#### 2. Главные правила (Git Flow)
В нашем репозитории есть две священные ветки, в которые **ЗАПРЕЩЕНО пушить код напрямую**:
* `main` — здесь лежит только 100% рабочий код (продакшн).
* `develop` — наша главная рабочая ветка. Здесь фронтенд объединяется с бэкендом и БД.

Вся работа ведется **ТОЛЬКО** в ваших личных фиче-ветках, которые вы создаете от `develop`. 
Названия веток должны быть понятными. Формат: `тип/модуль-суть-задачи`.
* `feat/` — для новых фич.
* `fix/` — для исправления багов.
* *Примеры:* `feat/frontend-login` (для Егора), `feat/db-schema` (для Миши), `feat/cloud-gateway` (для Дани).

#### 3. Как выглядит ваш рабочий процесс (Пошагово)

**Шаг 1. Перед началом новой задачи (Синхронизация)**
Убедитесь, что у вас самая свежая версия проекта:
```bash
git switch develop
git pull origin develop
```

**Шаг 2. Создание своей ветки**
Берете задачу из таск-трекера и создаете под нее ветку:
```bash
git switch -c feat/ваша-задача
```

**Шаг 3. Работа и сохранение коммитов**
Пишете код, проверяете, что всё работает. Делаете осмысленные коммиты:
```bash
git add .
git commit -m "feat: добавил форму авторизации" 
# (Пишите понятно, что именно сделали!)
```

**Шаг 4. Отправка на GitHub**
```bash
git push origin feat/ваша-задача
```

**Шаг 5. Создание Pull Request (PR)**
1. Заходите на GitHub.
2. Жмете зеленую кнопку **Compare & pull request**.
3. Проверяете, что сливаете свою ветку именно в **`develop`** (а не в `main`!).
4. Кидаете ссылку на PR мне в личку или в чат. Я (Андрей) смотрю код, аппрувлю и сливаю его в проект. После этого вашу фиче-ветку можно удалять.

#### 4. Пару важных мелочей:
* Не коммитьте пароли, ключи БД и токены! Используйте файлы `.env` (они уже добавлены в `.gitignore`, поэтому в репу не улетят).
* Если сомневаетесь или словили конфликт при слиянии (merge conflict) — ничего не удаляйте вслепую, пишите мне, разберемся вместе!
